# 模板创建指南（Agent 按此引导用户）

> 用途：用户提供甲方材料（风格参考 PDF/图片、文字要求、文案）加一句"制作一个模板 / 创建模板"（可能带"使用 dsimage"），Agent 分析并创建一个新模板。
> 用户不需要知道本文件存在——SKILL.md 已经规定：识别到"制作模板"类任务就读本文件。
> 术语：产出是一个「模板」JSON，存入模板库 `references/templates/`。模板 = 品牌风格 + 图内语言 + 图片包（pack）+ 执行流程（workflow），通过 pack 引用情景库 `references/scenes/` 的拍法。
> 前置必读：`references/templates/_TEMPLATE_SPEC.md`（模板字段规范）；拍摄方法参照 `references/scenes/` 情景库（25 个）。

## 流程总览：4 个固定检查点

**铁律：每个检查点必须停下来，等用户明确说"通过 / 可以 / 下一轮"才能继续；禁止跳轮，禁止一次性生成完整模板再让用户改。用户在任意轮次可要求返工本轮，返工后重新等确认。**

| 检查点 | 产出 | 通过条件 |
|---|---|---|
| 1. 素材分析 | 《风格分析报告》+ 口号翻译对照表 | 用户确认"提取准确" |
| 2. 模板骨架 + 情景盘查 | template_meta（品牌色板/字体/调性/语言）+ name/id/keywords/trigger_phrases + pack 草稿（槽位→情景→比例）+ 缺口情景的新建 | 用户确认品牌、图片包与新建情景 |
| 3. 执行流程 | workflow（5-8 步）+ text_rules + generation + 模板级 pitfalls 草稿 | 用户确认流程与数值 |
| 4. 成稿登记 | 完整 JSON + 校验通过 + 匹配表登记 + （可选）试跑图 | 校验通过且用户验收 |

---

## 检查点 1：素材分析

**做什么**：

1. 逐一查看用户提供的全部材料（PDF 渲染每页看、图片逐张看、文字要求逐条读）。
2. **取色必须给 hex**：优先用程序对参考页采样统计高频色；没有图像处理库时用宿主视觉估色，并列出 2-3 个候选让用户核对。禁止只凭感觉写一个色值。
3. 提取五要素：配色体系、版式结构（栏位/元素位置）、文字层级（主标题→副题→标注的字号关系）、产品呈现（占比/角度/背景）、光线调性。
4. 把甲方的**文字要求逐条翻译**成可执行参数（见下方"口号翻译规则"）。

**产出《风格分析报告》**，格式：

```text
1. 配色表：主色 #XXXXXX（第 N 页产品区采样）/ 辅色 #XXXXXX / 背景nth #XXXXXX / 文字色 #XXXXXX
2. 版式：整体结构、各元素位置
3. 文字层级：主标题特征 → 副题 → 标注
4. 产品呈现：占比、角度、背景处理
5. 口号 → 参数对照表（见下）
```

**等用户确认"提取准确，进入下一轮"。** 常见返工：hex 取偏、把装饰色当主色、版式层级看错。

### 口号翻译规则（硬性）

甲方原话**禁止直接写进模板**，必须逐条翻译成"字段 + 数值"。每轮产出附对照表，用户可拿去跟甲方对账：

| 甲方原话 | 翻译为 |
|---|---|
| 价格信息清晰、醒目 | `text_rules.price` = "价格 36-48pt，强调色 #xxxxxx，固定位置" |
| 产品图片突出 | `composition_rules.product_ratio` = "45-50%" |
| 专业、高级、简洁 | 配色 ≤3 个 hex + `whitespace` ≥40% + 单一字体家族 |
| 统一版式 | `workflow` 第一步按固定版式骨架，元素位置逐条声明 |
| 有销售力 | 补 CTA/卖点标签的 `text_rules`（短词 + 强调色） |

翻译不出数值的要求（如"感觉再高级一点"），在对照表中标注"待量化"，并给出你的建议值让用户选。

## 检查点 2：模板骨架

**做什么**（结构见 `_TEMPLATE_SPEC.md`）：

1. `name`（≤12 字中文名）、`id`（kebab-case，与文件名一致，模板层独立编号从 01 起）。
2. `keywords` ≥5 个、`trigger_phrases` ≥3 个——对照 SKILL.md 匹配表查重，说明"为什么不会误命中现有情景"。
3. `template_meta`：品牌色板 hex（来自检查点 1 的取色）、字体族、调性短语、图内文字语言。
4. `pack` 草稿：槽位列表，每个槽位 = slot 编号 + 用途 + 比例；用户要求几张就几个槽位。
5. **情景盘查（关键）**：为每个槽位在 `references/scenes/` 找最匹配的情景，写明引用文件；找不到匹配的（画面类型/拍法与现有情景差太远）→ 按情景规范 `_SCENE_SPEC.md` **当场新建情景**（序号接现有最大、只写拍法不带品牌、跑 check_scenes.py、在 SKILL.md 匹配表登记），模板用 pack 引用它。
6. 产出「槽位 → 情景」映射表（标注哪些是新建的），按槽位 H1 的情景骨架 + 品牌 hex 拼一条完整示例 Prompt 给用户看实际效果。

**等用户确认品牌方向、语言、图片包与新建情景。**

---

## 检查点 3：执行流程

**做什么**（数值全部来自检查点 1 的分析，不凭空写）：

1. `workflow`：5-8 步执行流程——读 pack 规划 → 建 Campaign Style Lock（用品牌 hex）→ 逐张"读引用情景 → 情景骨架 + 品牌 hex + text_rules 拼 Prompt" → 调 gen_image.py（--image）→ 检查 → 汇报；可按甲方要求特化（如报价表模板规定"价格必须人工确认后才渲染"）。
2. `text_rules`：每个文字角色的字号、hex、位置、长度上限（价格、标题、标注…逐个来）。
3. `generation`：resolution / format。
4. 模板级 `pitfalls`：3-5 条，来自甲方强调过的点（如"跨张版式漂移""价格乱码"）。

**等用户确认流程与数值。**

---

## 检查点 4：成稿与登记

**按顺序执行**：

1. 组装完整 JSON，写入 `references/templates/NN-xxx.json`（模板层独立编号，从 01 起；UTF-8，中文不转义）。
2. 运行 `python3 scripts/check_scenes.py`，**必须全部通过**；不通过就修，修完重跑。
3. 向用户展示完整模板内容 + `examples` 里 2 条成品 Prompt。
4. 在 SKILL.md 匹配表登记一行（触发词 | 文件名）；README 中情景数量如有提及则同步。
5. 询问用户是否用真实产品图试跑 1 张验证（会产生 API 费用须先征得同意；宿主自带生图则直接生成）。试跑图按情景 `pitfalls` 自查后一并展示。

**收尾汇报**：模板文件路径、匹配表登记情况、校验结果、试跑结论、修改模板的方法（直接改 JSON 再跑校验器）。
