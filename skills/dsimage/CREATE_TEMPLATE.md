# 模板创建指南（Agent 按此引导用户）

> 用途：用户说「制作一个模板 / 创建模板」，或一套品出完后确认要建模板。
> 用户不需要知道本文件存在。SKILL.md 规定命中这类任务就读本文件。
> **只有一种模板。** `lock=rules` 按规范画；`lock=master` 锁母版只换货。
> **一份模板 = 一个文件夹**，JSON 和图放一起。没有真图不要编一张充数。
> 顺序：定 lock → 建空文件夹 → **先把图拷进去** → 再写 JSON → 校验登记。不要先交一份没图的 JSON。
> 前置必读：`references/templates/_TEMPLATE_SPEC.md`。`lock=rules` 才需要 `references/scenes/`。

## 第 0 步：定 lock

对用户只问结果，不要问字段名：

| 用户带来的 | `lock` | 图够不够 |
|---|---|---|
| 成品套图 / 「按这套图换货」/ 「别的型号要长得一样」 | `master` | 每一页都要在。缺页不要用这个 lock，改走 `rules` |
| 品牌 PDF、色板、口号、版式说明，没有可当母版的成套成品图 | `rules` | 仍要至少 1 张示例（素材里的样张，或稍后验收的 H1） |
| 刚出完一套图，说要建模板 | 问：铺型号要像素级一致 → `master`（本轮成图当母版，**拷进模板夹**）；还要按规范再生 → `rules`（至少把本轮 H1 拷进去当示例） |

**每个检查点必须停下来，等用户说通过才能继续。禁止一次性生成完整模板。**

---

## 第 0.5 步：建文件夹（现在就建，不要等成稿）

**一个模板一个文件夹。** 不要建 `风格/`、`替换/`。匹配看 JSON 里的名字和触发词，不看路径有几层。整夹复制就能分享或挪位置，不要只拷 JSON。

编号接所在目录已有最大号。先建空夹，图和 JSON 都写进这里。

| 情况 | 建哪 |
|---|---|
| 就这一份、没有甲方 | `references/templates/NN-中文名/` |
| 同一甲方下面还有/还会有别的品 | `references/templates/{甲方id}/NN-中文名/`，甲方夹里要有 `要求.json` |
| 别人给了一个模板夹 | 整夹丢进 `templates/` 或某个甲方下。先确认夹里有图，再写入 `templates` 列表并登记匹配表 |
| 别人给了整个甲方夹 | 整夹放进 `templates/`，保留 `要求.json` |

有甲方时：

1. 已有 `references/templates/{甲方id}/` → 复用，先读 `要求.json`。
2. 没有 → 建文件夹。`id` = 文件夹名；不要用 `&`；真名写在 `要求.json` 的 `name`。
3. 写 `要求.json`：`templates`（模板目录名，不要带 `.json`）、`language`、`generation`、`style`、`brand`。给人看的说明可另写 `说明.md`。本品登记时把 `NN-中文名` 写进 `templates`。
4. 来自甲方的包若改成零散，先把 `要求.json` 的 `generation` / 语言 / brand 写进该模板 JSON。

拿不准问一句：「就这一份零散的，还是某个甲方下面的品？」零散的不要等甲方 id。

---

## 图从哪来（两套 lock 都要落盘）

图拷进**刚建的模板夹**，不要只留在 `generated-images/`、源品文件夹或聊天附件里。产品图不进模板夹。

| `lock` | 最少要有 | 从哪拷 | 文件名 |
|---|---|---|---|
| `rules` | 至少 1 张示例 | 甲方样张 / 风格页 / **本轮已验收的 H1** | 建议 `h1.png`，该槽写 `example` |
| `master` | **每一槽一张母版** | 用户给的成品套图 / **本轮已验收的整套成图** | 与 pack 的 `example` 一致（`h1.png`…） |

没有可拷的图：

- `rules`：检查点 4 之前必须先试跑 H1（API 费用先征得同意），验收通过再拷进模板夹。不许空着登记。
- `master`：停下来要齐套页。不要改走「先登记 JSON 以后再补图」。

## lock=rules：4 个检查点

| 检查点 | 产出 | 通过条件 |
|---|---|---|
| 1. 素材分析 | 《风格分析报告》+ 口号翻译对照表 + **哪张将当示例** | 用户确认提取准确，并点头示例从哪来 |
| 2. 模板骨架 + 情景盘查 | template_meta + pack（槽位→情景；H1 含 `example`） | 用户确认品牌、图片包、示例文件名与新建情景 |
| 3. 执行流程 | workflow + text_rules + generation + pitfalls | 用户确认流程与数值 |
| 4. 成稿登记 | 文件夹里已有 JSON **和** 示例图 + 校验 + 匹配表 | 校验通过且用户验收；夹里没图不准登记 |

### 检查点 1：素材分析

1. 逐一查看全部材料（PDF 渲染每页、图片逐张、文字逐条）。
2. **取色必须给 hex**：优先程序采样；没有图像库时用宿主视觉估色，列 2-3 个候选。
3. 提取五要素：配色、版式、文字层级、产品呈现、光线调性。
4. 甲方文字要求逐条翻译成可执行参数。
5. **选定示例图**：指出至少一张将放进模板夹的样张（哪一页、为什么够当 H1）。本轮刚出完图 → 用已验收的 H1。材料里没有样张 → 记下「检查点 4 先试跑再拷」。

产出：

```text
1. 配色表：主色 #XXXXXX / 辅色 #XXXXXX / 背景 #XXXXXX / 文字色 #XXXXXX
2. 版式：整体结构、各元素位置
3. 文字层级：主标题 → 副题 → 标注
4. 产品呈现：占比、角度、背景
5. 口号 → 参数对照表
6. 示例图来源：…… → 将存为 h1.png
```

**等用户确认「提取准确，进入下一轮」。**

| 甲方原话 | 翻译为 |
|---|---|
| 价格信息清晰、醒目 | `text_rules.price` = "价格 36-48pt，强调色 #xxxxxx，固定位置" |
| 产品图片突出 | `composition_rules.product_ratio` = "45-50%" |
| 专业、高级、简洁 | 配色 ≤3 个 hex + `whitespace` ≥40% + 单一字体家族 |
| 统一版式 | 元素位置逐条声明 |
| 有销售力 | 补 CTA/卖点标签的 `text_rules` |

翻译不出数值的标「待量化」，给建议值让用户选。

### 检查点 2：模板骨架

1. `name`（≤12 字）、`id`，`lock`: `rules`。
2. `keywords` ≥5、`trigger_phrases` ≥3（含「使用 dsimage 模板：{名}」），对照 SKILL.md 模板匹配表查重。
3. `template_meta`：只写本套差异（如 `style_source`）。`要求.json` 已有的 language / brand / generation 不要再抄进模板。
4. `pack` 草稿：slot + purpose + ratio + `overrides`。**H1（或选定那一槽）写 `example": "h1.png"`。** 品牌专用的占比、留白、文字位置写进模板或槽位 `overrides`，用来覆盖所引情景的默认；不要改情景文件迁就这一套。
5. **情景盘查**：每槽引用 `references/scenes/`；找不到则按 `_SCENE_SPEC.md` 当场新建情景。新建情景只写这一类图通用的拍法，品牌规则留在模板里。
6. 产出「槽位 → 情景」映射，按 H1 骨架 + 品牌 hex 拼一条示例 Prompt。
7. 手头已有样张 → **此刻拷进模板夹**，文件名与 `example` 一致。还没有则检查点 4 试跑后再拷。

**等用户确认品牌方向、语言、图片包、示例文件与新建情景。**

### 检查点 3：执行流程

1. `workflow`：先确认本模板文件夹名在 `要求.json` 的 `templates` 里。出图前打开文件夹里的示例图对照版式。然后 pack → Style Lock → 逐张「情景骨架 + 模板覆盖情景默认」拼 Prompt → `_prompts/` → 生成（参考图用用户产品图，不要把示例图当母版）→ 检查 → 汇报。generation 默认跟 `要求.json` 的 1k。组装时模板字段大于情景，不要折中。
2. `text_rules`：每个文字角色的字号、hex、位置、长度上限。
3. `generation`：零散模板必须自己写。有甲方则跟 `要求.json` 走，不要原样再抄一份；只有这一品不同才写进模板。
4. 模板级 `pitfalls`：3-5 条。这些模板共用的写进 `要求.json`。

**等用户确认流程与数值。**

### 检查点 4：成稿与登记

1. 把 JSON 写入已建的 `NN-中文名/NN-中文名.json`。有甲方则把该文件夹名写入 `要求.json` 的 `templates`。禁止覆盖。匹配表路径：`templates/NN-中文名/NN-中文名.json` 或 `templates/{甲方}/NN-中文名/NN-中文名.json`。
2. **确认模板夹里已有示例图**，且 pack 有槽位 `example` 指向它。还没有 → 先征得同意试跑 H1，验收后拷成 `h1.png`，再继续。不要编假图，不要空夹登记。
3. `python scripts/check_scenes.py` 必须全部通过（缺图会失败）。
4. 在 SKILL.md **模板匹配表**登记一行。
5. 已有示例则询问是否再试跑；示例就是刚试跑的那张则不必再跑。

## lock=master：4 个检查点

不要取色当主产出，不要盘查情景，不要写构图 overrides。母版图是模板本体。**没有齐套成品页就不要走这一节**，改走 `lock=rules`，先留示例图。

| 检查点 | 产出 | 通过条件 |
|---|---|---|
| 1. 母版盘点 + 落盘 | 页清单 + 模板夹里已有全部母版文件 | 用户确认页序、用途，并看到文件已进夹 |
| 2. pack 骨架 | slot → example → product_ref；允许改的字段 | 用户确认映射和 editable_fields；每个 `example` 在夹里 |
| 3. 换货流程 | workflow + text_rules.policy + pitfalls | 用户确认未点名不动 |
| 4. 成稿登记 | JSON + 齐套母版 + 校验 + 匹配表 | 校验通过且用户验收；缺一槽不准登记 |

### 检查点 1：母版盘点 + 落盘

1. 把用户给的套图（或本轮成图）按页看完。
2. 产出页清单：文件名、用途、产品朝向（正/背/侧/细节/配色）、图上已有文字。
3. 标出哪些字以后换型号时可能要改（默认全部冻住）。
4. 品类写一句；外形差太远的货不要硬换。
5. **按拟定文件名把每一页拷进模板夹**（建议 `h1.png`、`h2.png`…）。从 `generated-images/` 拷贝，不要只引用原路径。缺任何一页就停下来要图，不要进入检查点 2。

**等用户确认页序、用途、哪些字默认可改、文件已在夹里。**

### 检查点 2：pack 骨架

1. `name` / `id`，`lock`: `master`。`trigger_phrases` 含「使用 dsimage 模板：{名}」。
2. 每页一个槽：`slot`、`purpose`、`example`、`product_ref`、`ratio`。`example` 必须是夹里已有的文件名。
3. **不要写 `scene`，不要写构图 overrides。**
4. `text_rules.editable_fields`：用户点名的才列入，否则 `[]`。

**等用户确认槽位映射和可改字段。**

### 检查点 3：换货流程

1. `workflow` 必须是换货：读 pack 与本文件夹母版 → 按 product_ref 选产品图 → 缺角度先问 → Prompt 只写换品+点名字段 → `_prompts/` + `image: [母版, 产品图]` → 对照母版检查 → 汇报。
2. `text_rules.policy`：未点名的文字、图标、版式、背景保持母版原样。
3. `pitfalls`：有母版却按情景重画；未点名改字；缺角度硬贴。
4. `generation`：零散的写在模板里；有甲方则跟 `要求.json` 走，不要原样再抄一份。

**等用户确认流程。**

### 检查点 4：成稿与登记

1. 把 JSON 写入已建的模板夹（与母版图同夹）。有甲方则把该文件夹名写入 `要求.json` 的 `templates`。**缺任何一槽母版不准登记**，不要编假图。
2. `python scripts/check_scenes.py` 必须通过。
3. 在 SKILL.md **模板匹配表**登记。
4. 询问是否拿一个新品号试换 1 张。

**收尾**：以后翻车换该槽母版或改 `editable_fields`，不要改 `lock`、不要新建情景。
