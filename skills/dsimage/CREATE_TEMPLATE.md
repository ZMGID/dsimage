# 模板创建指南（Agent 按此引导用户）

> 用途：用户提供甲方材料加一句"制作一个模板 / 创建模板"（可能带"使用 dsimage"），或**一套品出完后确认要建模板**，Agent 分析并创建一个新模板。
> 用户不需要知道本文件存在——SKILL.md 已经规定：识别到"制作模板"类任务、或出图后用户同意建模板，就读本文件。
> 模板分两种，**先判定再走对应检查点**，不要混：
> - **风格模板**：锁规则（色板、字体、构图、引用情景）。还没有定稿套图时用。
> - **替换模板**：锁母版套图 + 一份换货说明。已有成品套图、后面只铺不同型号时用。
> 产出：零散模板直接写入 `references/templates/` 根目录；同一甲方多个品才建文件夹，先写 `要求.json`，再把这个品的 JSON 放进 `风格/` 或 `替换/`（替换另加同名文件夹母版图）。
> 前置必读：`references/templates/_TEMPLATE_SPEC.md`。风格模板才需要 `references/scenes/`。

## 先判定类型（第 0 步）

对用户说「换品母版」或「风格规则」，不要问 `template_type`。拿不准用 SKILL.md「意图引导」的问法。材料已经够清楚就不要再问一遍：

| 用户带来的 | 建哪种 |
|---|---|
| 成品套图 / 「按这套图换货」/ 「别的型号要长得一样」 | **替换**（换品母版） |
| 品牌 PDF、色板、口号、版式说明，没有可当母版的成套成品图 | **风格** |
| 刚出完一套图，说要建模板 | 问：铺型号要像素级一致 → 替换（本轮成图当母版）；还要按规范再生 → 风格 |

**铁律：每个检查点必须停下来，等用户明确说"通过 / 可以 / 下一轮"才能继续；禁止跳轮，禁止一次性生成完整模板再让用户改。**

---

## 放哪（第 0.5 步）

不要每个模板都建一个文件夹。

| 情况 | 放哪 |
|---|---|
| 就这一份、没有甲方、零散 | `references/templates/NN-中文名.json`（替换再加同名母版文件夹）。编号接根目录已有最大号 |
| 同一甲方下面还有/还会有别的品，要求大差不差 | `{甲方id}/` + `要求.json`，这个品进 `风格/` 或 `替换/` |

有甲方时：

1. 已有 `references/templates/{甲方id}/` → 复用，先读 `要求.json`，共用要求没变就不要重写。
2. 没有 → 建文件夹。`id` = 文件夹名；不要用 `&`（Windows）；`BEAUTY&U` 用 `BeautyU`，真名写在 `要求.json` 的 `name`。
3. 写 `要求.json`：`language`、`generation`（分辨率/格式）、`style`、`brand`。给人看的说明可另写 `说明.md`。
4. 建空的 `风格/`、`替换/`。编号接**该目录**已有最大号。

材料已经能看出是零散还是某甲方，就不要再问。拿不准问一句：「就这一份零散的，还是某个甲方下面的品？」

**零散的不要等甲方 id。** 有甲方且要求没变，确认后进下面的检查点。

## 风格模板：4 个检查点

| 检查点 | 产出 | 通过条件 |
|---|---|---|
| 1. 素材分析 | 《风格分析报告》+ 口号翻译对照表 | 用户确认"提取准确" |
| 2. 模板骨架 + 情景盘查 | template_meta + pack（槽位→情景）+ 缺口情景的新建 | 用户确认品牌、图片包与新建情景 |
| 3. 执行流程 | workflow + text_rules + generation + pitfalls | 用户确认流程与数值 |
| 4. 成稿登记 | JSON + 校验 + 匹配表 | 校验通过且用户验收 |

### 检查点 1：素材分析

1. 逐一查看全部材料（PDF 渲染每页看、图片逐张看、文字要求逐条读）。
2. **取色必须给 hex**：优先程序采样；没有图像库时用宿主视觉估色，列 2-3 个候选。禁止只凭感觉写一个色值。
3. 提取五要素：配色、版式、文字层级、产品呈现、光线调性。
4. 甲方文字要求逐条翻译成可执行参数（见下方"口号翻译规则"）。

产出《风格分析报告》：

```text
1. 配色表：主色 #XXXXXX / 辅色 #XXXXXX / 背景 #XXXXXX / 文字色 #XXXXXX
2. 版式：整体结构、各元素位置
3. 文字层级：主标题 → 副题 → 标注
4. 产品呈现：占比、角度、背景
5. 口号 → 参数对照表
```

**等用户确认"提取准确，进入下一轮"。**

#### 口号翻译规则（硬性）

甲方原话**禁止直接写进模板**，必须逐条翻译成"字段 + 数值"：

| 甲方原话 | 翻译为 |
|---|---|
| 价格信息清晰、醒目 | `text_rules.price` = "价格 36-48pt，强调色 #xxxxxx，固定位置" |
| 产品图片突出 | `composition_rules.product_ratio` = "45-50%" |
| 专业、高级、简洁 | 配色 ≤3 个 hex + `whitespace` ≥40% + 单一字体家族 |
| 统一版式 | `workflow` 第一步按固定版式骨架，元素位置逐条声明 |
| 有销售力 | 补 CTA/卖点标签的 `text_rules`（短词 + 强调色） |

翻译不出数值的要求标注"待量化"，给出建议值让用户选。

### 检查点 2：模板骨架

1. `name`（≤12 字）、`id`（与文件名中文名一致），`template_type`: `style`。
2. `keywords` ≥5、`trigger_phrases` ≥3，对照 SKILL.md **风格模板匹配表**查重。
3. `template_meta`：品牌色板 hex、字体族、调性、图内文字语言。
4. `pack` 草稿：slot + purpose + ratio + `overrides`（只写与情景默认的差异）。
5. **情景盘查**：每槽引用 `references/scenes/`；找不到则按 `_SCENE_SPEC.md` 当场新建情景（序号接最大、只写拍法、跑校验、匹配表登记）。
6. 产出「槽位 → 情景」映射，按 H1 骨架 + 品牌 hex 拼一条示例 Prompt。

**等用户确认品牌方向、语言、图片包与新建情景。**

### 检查点 3：执行流程

1. `workflow`：有甲方则先读 `要求.json`；零散的只读本模板。然后 pack → Style Lock → 逐张情景骨架 + 品牌 hex + text_rules 拼 Prompt → Prompt/jobs.json 按 SKILL「落盘」写入 `_prompts/` → `gen_image.py --batch` 或子代理并行 → 检查 → 汇报。generation 默认 1k。
2. `text_rules`：每个文字角色的字号、hex、位置、长度上限。
3. `generation`：零散模板必须自己写。有甲方则跟 `要求.json` 走，这个品要 2k / jpeg 才覆盖。
4. 模板级 `pitfalls`：3-5 条。只跟这一品有关的才写这里；全甲方共用的写进 `要求.json`。

**等用户确认流程与数值。**

### 检查点 4：成稿与登记

1. 零散写入 `references/templates/NN-中文名.json`，编号接根目录已有最大号。有甲方写入 `references/templates/{甲方}/风格/NN-中文名.json`，编号接该甲方 `风格/` 已有最大号。禁止覆盖。
2. `python scripts/check_scenes.py` 必须全部通过。
3. 展示完整模板 + `examples` 里 2 条成品 Prompt。
4. 在 SKILL.md **风格模板匹配表**登记一行（路径按实际位置）。
5. 询问是否试跑 1 张（API 费用须先征得同意）。

**收尾**：模板路径、匹配表、校验结果、试跑结论。全甲方共用（语言/分辨率/风格）→ `要求.json`；零散的写在模板自己里。这一品的版式 → 槽位 `overrides`；拍法坑 → 情景 pitfalls。

## 替换模板：4 个检查点

不要取色当主产出，不要盘查情景，不要写构图 overrides。母版图是模板本体。

| 检查点 | 产出 | 通过条件 |
|---|---|---|
| 1. 母版盘点 | 页清单 + 每页用途/产品角度 + 图上已有文字 | 用户确认页序和用途 |
| 2. pack 骨架 | slot → example 文件名 → product_ref；允许改的字段 | 用户确认映射和 editable_fields |
| 3. 换货流程 | workflow + text_rules.policy C + pitfalls | 用户确认「未点名不动」 |
| 4. 成稿登记 | JSON + 同名文件夹母版图 + 校验 + 匹配表 | 校验通过且用户验收 |

### 检查点 1：母版盘点

1. 把用户给的套图（或本轮成图）按页看完，不要只看第一张。
2. 产出页清单：文件名、画面用途、产品朝向（正/背/侧/细节/配色）、图上已有文字（标题、卖点、REF、价格）。
3. 标出哪些字以后换型号时可能要改（默认全部冻住）。
4. 品类写一句（如双肩包），外形差太远的货不要用这套母版硬换。

**等用户确认页序、用途、哪些字默认可改。**

### 检查点 2：pack 骨架

1. `name` / `id`，`template_type`: `replace`。`trigger_phrases` 至少含「使用 dsimage 替换模板：{名}」，对照 SKILL.md **替换模板匹配表**查重。
2. 每页一个槽：`slot`、`purpose`、`example`（`h1.png`…）、`product_ref`（`front` / `back` / `side` / `detail` / `colorway`）、`ratio`。
3. **不要写 `scene`，不要写构图 overrides。**
4. `text_rules.editable_fields`：用户点名的才列入（`sku` / `price` / `color_name` / `product_name` / `currency`），否则 `[]`。
5. 把母版图复制到待登记的同名文件夹草稿，文件名与 `example` 一致。出图后转来的，用本轮成图，不要让用户再交一遍。

**等用户确认槽位映射和可改字段。**

### 检查点 3：换货流程

1. `workflow` 必须是换货，不是再生。标准步骤：读 pack 与母版 → 按 product_ref 选产品图 → 缺角度/品类差太远先问 → Prompt 只写换品+点名字段 → `_prompts/` + `image: [母版, 产品图]` → 对照母版检查 → 汇报。
2. `text_rules.policy` 写死：未点名的文字、图标、版式、背景保持母版原样。
3. `pitfalls`：把替换当风格重画；未点名改字；缺角度硬贴；品类差太远硬换。
4. `generation`：零散的写在模板里；有甲方则跟 `要求.json` 走，这个品不一样才覆盖。

**等用户确认流程。**

### 检查点 4：成稿与登记

1. 零散：JSON 写入 `references/templates/NN-中文名.json`，母版写入 `references/templates/NN-中文名/`。有甲方：JSON 写入 `references/templates/{甲方}/替换/NN-中文名.json`，母版写入同名文件夹。编号接所在目录已有最大号，禁止覆盖。
2. `python scripts/check_scenes.py` 必须通过（会检查每个 example 文件存在）。
3. 展示页映射 + 可改字段；在 SKILL.md **替换模板匹配表**登记「使用 dsimage 替换模板：{名}」。
4. 询问是否拿一个新品号试换 1 张（须先征得同意）。

**收尾**：JSON 路径、母版文件夹、校验结果。以后翻车换该槽母版或改 `editable_fields`，不要改成风格模板、不要新建情景。
