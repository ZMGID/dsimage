# 模板创建指南（Agent 按此引导用户）

> 用途：用户提供甲方材料（风格参考 PDF/图片、文字要求、文案），Agent 分析并创建一个新模板。
> 触发示例："读取 CREATE_TEMPLATE.md，根据这些材料建一个模板"。
> 前置必读：`references/templates/_TEMPLATE_SPEC.md`（字段规范）；写作风格参照现有 25 个模板。

## 流程总览：4 个固定检查点

**铁律：每个检查点必须停下来，等用户明确说"通过 / 可以 / 下一轮"才能继续；禁止跳轮，禁止一次性生成完整模板再让用户改。用户在任意轮次可要求返工本轮，返工后重新等确认。**

| 检查点 | 产出 | 通过条件 |
|---|---|---|
| 1. 素材分析 | 《风格分析报告》+ 口号翻译对照表 | 用户确认"提取准确" |
| 2. 模板骨架 | name/id/keywords/trigger_phrases/prompt_template/variants 草稿 + 示例 Prompt | 用户确认骨架方向 |
| 3. 执行规则 | default_ratio/composition_rules/text_rules/workflow/pitfalls 草稿 | 用户确认数值 |
| 4. 成稿登记 | 完整 JSON + 校验通过 + 匹配表登记 + （可选）试跑图 | 校验通过且用户验收 |

---

## 检查点 1：素材分析

**做什么**：

1. 逐一查看用户提供的全部材料（PDF 渲染每页看、图片逐张看、文字要求逐条读）。
2. **取色必须给 hex**：优先用程序对参考页采样统计高频色；没有图像处理库时用宿主视觉估色，并列出 2-3 个候选让用户核对。禁止只凭感觉写一个色值。
3. 提取五要素：配色体系、版式结构（栏位/元素位置）、文字层级（主标题→副题→标注的字号关系）、产品呈现（占比/角度/背景）、光线调性。
4. 把甲方的**文字要求逐条翻译**成可执行参数（见下方"口号翻译规则"）。

**产出《风格分析报告》**，格式：

```text
1. 配色表：主色 #XXXXXX（第 N 页产品区采样）/ 辅色 #XXXXXX / 背景nth #XXXXXX / 文字色 #XXXXXX
2. 版式：整体结构、各元素位置
3. 文字层级：主标题特征 → 副题 → 标注
4. 产品呈现：占比、角度、背景处理
5. 口号 → 参数对照表（见下）
```

**等用户确认"提取准确，进入下一轮"。** 常见返工：hex 取偏、把装饰色当主色、版式层级看错。

### 口号翻译规则（硬性）

甲方原话**禁止直接写进模板**，必须逐条翻译成"字段 + 数值"。每轮产出附对照表，用户可拿去跟甲方对账：

| 甲方原话 | 翻译为 |
|---|---|
| 价格信息清晰、醒目 | `text_rules.price` = "价格 36-48pt，强调色 #xxxxxx，固定位置" |
| 产品图片突出 | `composition_rules.product_ratio` = "45-50%" |
| 专业、高级、简洁 | 配色 ≤3 个 hex + `whitespace` ≥40% + 单一字体家族 |
| 统一版式 | `workflow` 第一步按固定版式骨架，元素位置逐条声明 |
| 有销售力 | 补 CTA/卖点标签的 `text_rules`（短词 + 强调色） |

翻译不出数值的要求（如"感觉再高级一点"），在对照表中标注"待量化"，并给出你的建议值让用户选。

## 检查点 2：模板骨架

**做什么**：

1. `name`（≤12 字中文名）、`id`（kebab-case，与文件名一致，序号取现有最大 +1）。
2. `keywords` ≥5 个、`trigger_phrases` ≥3 个——对照 SKILL.md 匹配表查重，说明"为什么不会误命中现有模板"。
3. `prompt_template`：以检查点 1 的分析填充骨架（background/lighting 用取到的 hex 和光线调性）。
4. `variants` 2-4 个（只写 overrides），贴合甲方可能的使用场景。
5. 拼一条完整示例 Prompt 给用户看实际效果。

**等用户确认骨架方向和触发边界。**

---

## 检查点 3：执行规则

**做什么**（数值全部来自检查点 1 的分析，不凭空写）：

1. `default_ratio`：按甲方材料的画幅。
2. `composition_rules`：product_ratio / whitespace / angles（带英文短语）/ platform_reserved 或 layout（如适用）。
3. `text_rules`：每个文字角色的字号、hex、长度上限（价格、标题、标注…逐个来）。
4. `workflow`：4-6 步，场景特化，第一步通常是"按甲方固定版式排版"。
5. `pitfalls`：3-5 条，来自甲方强调过的点 + 该场景固有风险。

**等用户确认数值。**

---

## 检查点 4：成稿与登记

**按顺序执行**：

1. 组装完整 JSON，写入 `references/templates/NN-xxx.json`（UTF-8，中文不转义）。
2. 运行 `python3 scripts/validate_templates.py`，**必须全部通过**；不通过就修，修完重跑。
3. 向用户展示完整模板内容 + `examples` 里 2 条成品 Prompt。
4. 在 SKILL.md 匹配表登记一行（触发词 | 文件名）；README 中模板数量如有提及则同步。
5. 询问用户是否用真实产品图试跑 1 张验证（会产生 API 费用须先征得同意；宿主自带生图则直接生成）。试跑图按模板 `pitfalls` 自查后一并展示。

**收尾汇报**：模板文件路径、匹配表登记情况、校验结果、试跑结论、修改模板的方法（直接改 JSON 再跑校验器）。
